# Working rules

Read `docs/README.md` first. The architecture and design principles in this file are mandatory.

## Layers

| Layer      | Location                                                       | Rule                                                                                                                                      |
| ---------- | -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Entry      | `app/Http/Controllers`, `app/Console/Commands`, `routes/*.php` | Validate with a Form Request, call one service, return an Inertia page, redirect, or resource. No queries beyond loading the route model. |
| Validation | `app/Http/Requests`                                            | Typed accessor methods (`profile()`, `roleIds()`) hand clean data to services.                                                            |
| Services   | `app/Services/<Area>`                                          | One use case each. Own the transaction. Write the audit row inside it.                                                                    |
| Domain     | `app/Domain/<Area>`                                            | Pure. No I/O, no clock, no `config()`, no facades. Pass `now`, IDs, and settings in.                                                      |
| Queries    | `app/Queries`                                                  | Read models for list screens. Always paginated through `PaginationSettings::clamp()`.                                                     |
| Models     | `app/Models`                                                   | Relations, casts, scopes. Tenant models use `BelongsToBarangay`.                                                                          |
| Config     | `config/bms.php` → `App\Support\Config\BmsSettings`            | Only place that reads env. Validated at boot.                                                                                             |
| Text       | `lang/en/*.php`, `resources/js/i18n/en.json`                   | Every user-facing string.                                                                                                                 |
| Contracts  | `resources/js/contracts/generated.ts`                          | Generated by `php artisan bms:contracts:generate`. Never edit by hand.                                                                    |

## Hard rules

1. No explanatory comments in code. Put the why in `docs/`. Type annotations for PHPStan and Vue are allowed.
2. No magic values. Statuses, roles, permissions, flags, actions, document kinds: enums in `app/Enums`. Cache keys: `App\Support\CacheKeys`. Route names used in PHP: `App\Support\RouteNames`. Limits and widths: `config/bms.php` or a named class constant.
3. Every schema change is a new migration. Never edit a migration that has run anywhere outside your machine.
4. Stored JSON carries a version field (`audit_events.changes.v`). Readers accept every listed version.
5. Every new tenant table has a non-null `barangay_id`, an index starting with it, and a model using `BelongsToBarangay`.
6. Every new optional or risky behavior gets a flag: enum case, `FlagCatalog` entry, `lang/en/features.php` text, route middleware or service check. Release flags need `removeAfter`.
7. Every new permission: enum case, `RoleCatalog` assignment, `lang/en/permissions.php` text, then `bms:contracts:generate`.
8. The server is authoritative. The frontend may hide controls by permission or flag; the server always enforces.
9. American English in code, UI, and docs.

## Commands

```sh
composer test                     # lint, PHPStan, contract check, tests
npm run check && npm run types:check
php artisan bms:contracts:generate
```

All tooling runs inside the development container.
